## 0. 对现状诊断（3 分钟看懂"为什么必须改"）

从 7 张截图反推，当前视觉系统的成本集中在六处：

| # | 现状 | 实测问题 | 后果 |
|---|---|---|---|
| A | 卡片用「双层描边 + 外发光 + 四角小三角 + 斜切角」建立层次 | 单个卡片装饰伪元素 ≥ 6 个 | 8 个卡片并排后形成一片光墙，层次反而消失 |
| B | 发光即层次 | 卡片边界 `box-shadow: 0 0 20px rgba(0,150,255,.5)` | 亮度溢出导致文字被"吃掉"，12px 文本实际可读性接近 0 |
| C | 图表配色为彩虹 / 蓝紫双色 | 仪表盘红→橙→黄→绿四段；环形橙+紫 | 颜色不再携带语义，读者无法区分"值"与"状态" |
| D | 板块标题存在 ≥ 3 种形态 | `深度分析 ›` / `诊断多帐率 ` / `❬ 标题 ` / `标题 ▸` | 视线无法建立统一锚点，扫视效率低 |
| E | 底部导航 ~70px 且 `position:fixed` 覆盖内容 | 劳动改造页「禁止性情形安排」、监管改造页柱图基线被压掉 | 数据被物理裁切，属于交付级缺陷 |
| F | 表格正文 8–10px、行高 1.1–1.3 | 监管改造表 6 列挤在 40% 宽度内 | 3 米外完全不可读；右侧「申请事由」列被硬切 |

结论：问题不是"不够炫"，而是**层次表达手段单一（只有发光）**。所以本方案的第一性动作是——**把层次从"光"迁移到"排版 + 描边 + 底色阶差 + 留白"**，一次性关掉所有发光与斜切。

## 1. 设计立场（5 条，每条都附带可判断的取舍标准）

### 立场 1｜层次靠"阶差"不靠"光"

深浅四档背景（ΔL\* 约 4.5 / 7.9 / 10.9 / 15.7）+ 1px 描边 + 精确内边距，构成全部层次。
**取舍标准**：把全站 `box-shadow` 全部设成 `none` 后截图，如果仍能一眼分出「画布 / 区块 / 卡片 / 悬浮层」四层，方案成立；分不出则加描边对比或底色阶差，**不允许**用回发光。

**为什么放弃外发光**
1. 发光是"面积性亮度"，会抬高整块区域的感知亮度，直接压缩该区域内文字的对比度余量——这是原页面"很亮但看不清"的根因。
2. 发光无法编码差异。当 8 个卡片都在发光时，发光就不再是"强调"，沦为背景纹理。
3. 发光在 LED 大屏上会因背光溢出（bloom）二次扩散，实际观感比设计稿更糊，且不同屏体差异极大，不可控。
4. 政务指挥场景的语义是"准确、可追溯、可复核"，光效的语义是"娱乐、展示、氛围"——两者冲突。

**为什么放弃 3D 斜切边框**
1. 斜切（`clip-path` 切角 / 伪元素拼三角）本质上是在 1px 的空间里塞进 3 个视觉层级，与"精确"直接对立。
2. 切角破坏了矩形的对齐基准面，导致相邻卡片即使栅格对齐，视觉上也不齐——这正是原页面"看起来乱"的隐形来源。
3. 切角在响应式下必须随尺寸重算，是纯负担，换不来任何信息。

### 立场 2｜全站一个色相，语义色有"执照"

全站装饰性色相**只有 1 个**（政务蓝）。橙/红/青绿三个语义色**仅在有状态需要表达时才允许出现**。
**取舍标准**：任取一个像素问"这个颜色在说什么"，必须能答出具体状态；答不出（"为了好看"）即为违规。落地检查：全站颜色值必须来自 §2 token 表，禁止裸 HEX。

### 立场 3｜克制的对比度区间，而不是"越亮越好"

深色大屏的舒适对比区间是 **8:1 ~ 5:1**，不是 15:1。纯白 `#FFFFFF` 在深底上会因视觉晕光（halation）变粗，因此主文字用 `#DCE5EE`（13.2:1），大数字用 `#F2F6FA`（15.5:1），**永不使用纯白**。
**取舍标准**：正文类文字对比度 ∈ [4.5, 10]；超过 12 的文字仅允许出现在 ≥28px 的数字上。

### 立场 4｜字号有地板，密度靠行高不靠缩字

正文地板 **12px**（1920 基准），且 12px 只允许承载"次要口径"；承载判断依据的数据正文用 **14px**。
**取舍标准**：任何一列数据在 3 米外看不清 → 只能加字号或减少同屏列数，**禁止**用缩小字号来塞内容。

### 立场 5｜每个装饰像素都要有信息产权

首页中间区（916×420px 以上）是全站最大的一块"地"，原设计用来放 3D 地球 + 9 个浮动标签，信息熵为 0。
**取舍标准**：任一区域若删掉后不损失任何数据、层级或交互线索，则它不该存在。球体、旋转环、粒子、扫描线、装饰刻度、装饰雷达网格——全部删除。

## 2. 色板（精确 HEX + 用途 + 实测对比度）

### 2.1 背景层级（4 级）

| Token | HEX | CIE L\* | 相对上一级 ΔL\* | 用途 |
|---|---|---|---|---|
| `--bg-canvas` | `#0B1017` | 4.5 | — | 页面画布底、顶部栏底、底部导航底 |
| `--bg-region` | `#101822` | 7.9 | +3.4 | 区块底（列容器）、表头底、输入框底、Tab 未激活底 |
| `--bg-card` | `#141E2A` | 10.9 | +2.9 | 业务卡片底（全站主用） |
| `--bg-elevated` | `#1C2836` | 15.7 | +4.8 | 悬浮层：下拉、Popover、Tooltip、模态、行 hover 峰值 |

**阶差设定依据**：ΔL\* ≥ 2 是人眼在深色背景下的可辨识阈值，ΔL\* ≥ 4 才不刺眼。本例三档分别 3.4 / 2.9 / 4.8，全部落在"可辨识但不刺眼"区间。
**禁用**：不得新增第 5 级背景；不得用透明度叠加造新底色（会导致阶差不稳定）。

### 2.2 中性色阶（7 级）

对比度基准 = 卡片底 `#141E2A`（L = 0.01244）。

|---|---|---|---|---|
| N0 | `--neutral-0` | `#F2F6FA` | **15.5 : 1** | 主 KPI 大数字（≥28px）、仪表中心值、表格首列强调值 |
| N1 | `--neutral-1` | `#DCE5EE` | **13.2 : 1** | 一级标题、卡片标题、表格首列文本、导航激活项 |
| N2 | `--neutral-2` | `#B4C2D0` | **9.3 : 1** | 表格正文、正文强调、按钮文字（次级）、图例文字 |
| N3 | `--neutral-3` | `#8494A6` | **5.4 : 1** | 正文默认（14px 以下）、轴标签、口径副标、表头文字、图例、单位 |
| N4 | `--neutral-4` | `#5F6E80` | **3.2 : 1** | 占位文本、禁用文字、装饰性标签、序号角标 —— **禁止承载数据** |

**描边三档**（与中性色阶分开，避免误用）：

| Token | HEX | 对卡片底对比度 | 用途 |

### 2.3 主色（政务蓝，1 支 + 变体）

| Token | HEX | 说明 | 对比度 |
|---|---|---|---|
| `--blue-600` | `#2F74C0` | **实底填充**（主按钮底、选中指示条）| 白字 **4.79 : 1** ✓ |
| `--blue-500` | `#4A8CD4` | 实底 hover | — |
| `--blue-700` | `#2664A8` | 实底 active/pressed | — |
| `--blue-400` | `#77A9E1` | **深底上的蓝**（文字/图标/折线/焦点环）| vs 卡片底 **6.8 : 1** ✓ |
| `--blue-300` | `#ABC8EC` | 蓝底上的次要文字 | — |
| `--blue-tint` | `rgba(82,144,218,0.14)` | 选中行底、图表面积填充 | — |

### 2.4 语义色（3 支，各 2 形态）

| 状态 | 文字色 | 卡片底对比度 | 底色形态 | 描边形态 | 唯一允许出现的位置 |
|---|---|---|---|---|---|
| 正常 / 达标 | `--ok-text` `#3FC1A7` | **7.5 : 1** | `rgba(63,193,167,0.12)` | `rgba(63,193,167,0.32)` | 达标徽标、下载量、环比向好、正常状态点 |
| 预警 / 关注 | `--warn-text` `#DC9F46` | **7.3 : 1** | `rgba(220,159,70,0.12)` | `rgba(220,159,70,0.32)` | 预警条目、阈值接近、待处理计数 |
| 危险 / 超限 | `--danger-text` `#E5746E` | **5.7 : 1** | `rgba(229,116,110,0.12)` | `rgba(229,116,110,0.32)` | 严重预警、超时、超阈值、环比恶化 |

**硬规则**
- 语义色**只表达状态**：不得用于标题、tab 激活、按钮、装饰线、图表默认配色。
- 三色的亮度已人为拉齐（L ≈ 0.28~0.42），因此**不能只靠颜色区分优先级**（也符合无障碍要求）。必须叠加文字标签 + 位置排序，见 §5.5。
- 危险红文字版为 `#E5746E`（5.7:1）；若要做实底填充，用 `#C9403C` 配白字（**4.90:1**，仍达标）。

### 2.6 明确禁用清单

```
禁止 外发光         box-shadow / drop-shadow / text-shadow 中出现任何非黑色透明色
禁止 彩色阴影       shadow 颜色只允许 rgba(0,0,0,x)，x ≤ 0.45
禁止 阴影 > 2 层    单元素 box-shadow 层数 ≤ 2

禁止 渐变描边       border-image / background 渐变伪造边框

禁止 彩虹色阶       仪表盘 / 环形图不得出现 ≥3 色相的分段渐变
禁止 纯白文字       #FFFFFF 仅允许出现在蓝实底按钮内的白字
禁止 纯黑底         #000000 不得作为任何底色

禁止 多色面积渐变    面积填充仅允许单色 → 透明的单向渐变
```

## 3. 字体系统

### 3.1 字体族与 fallback 栈

```css
/* 中文 + 通用 UI */
--font-sans: "HarmonyOS Sans SC", "Source Han Sans SC", "Noto Sans SC",
             "PingFang SC", "Microsoft YaHei", "Hiragino Sans GB",
             system-ui, -apple-system, "Segoe UI", sans-serif;

/* 数字 / 拉丁字符（用于数值、时间戳、轴标签） */
--font-num:  "Inter", "SF Pro Text", "Segoe UI", "DIN Next",
             "Helvetica Neue", Arial, sans-serif;
```

选择依据：HarmonyOS Sans SC 与思源黑体的字面率接近、字重覆盖 300–700 完整，且 HarmonyOS Sans 的数字为等宽友好设计，适合表格；苹方在 Windows 指挥终端上不存在，因此**必须**把 Microsoft YaHei 放在苹方之后兜底。

### 3.2 字号阶梯（1920×1080 基准）

| Token | 字号 | 行高 | 字重 | 字距 | 用途 |
|---|---|---|---|---|---|
| `--fs-display` | **44px** | 48px | 600 | −0.5px | 首页全局主 KPI、仪表中心值 |
| `--fs-metric` | **32px** | 38px | 600 | −0.2px | 卡片内 KPI 数值 |
| `--fs-h1` | **26px** | 34px | 600 | +0.5px | 页面标题（监管改造 / 劳动改造 …） |
| `--fs-h2` | **18px** | 26px | 600 | +0.3px | 板块标题（§5.2） |
| `--fs-h3` | **15px** | 22px | 500 | +0.2px | 卡片内小标题、表格表头 |
| `--fs-body` | **14px** | 22px | 400 | 0 | 正文、表格正文、预警条目标题 |
| `--fs-sm` | **13px** | 20px | 400 | 0 | 次级说明、按钮文字、图例、单位 |
| `--fs-xs` | **12px** | 18px | 400 | +0.2px | **最小档**：口径副标、轴标签、时间戳、序号 |
| `--fs-micro` | ~~11px~~ | — | — | — | **已废弃，不得使用** |

**地板规则**：`--fs-xs` 12px 是绝对下限，**且仅允许承载非判断性信息**（口径、单位、时间、来源、序号）。任何"读它来做决定"的文本必须 ≥14px。

### 3.3 字重使用规则

| 字重 | 允许场景 |
|---|---|
| 300 Light | **全站禁用**（深底上会发虚） |
| 400 Regular | 所有正文、表格、图例、轴标签、口径 |
| 500 Medium | 表头、按钮、h3、预警条目标题、数值标签 |
| 600 Semibold | h1 / h2 / display / metric / 板块标题 / 徽标文字 |
| 700 Bold | **全站禁用**（唯一例外：蓝实底按钮内 13px 白字可用 500，不升 700）|

> 用字重建立层级的上限是 2 档（400 / 600）。原页面在同一屏里出现 4 档字重，是"乱"的另一来源。

### 3.4 数字排印

```css
.num {
  font-family: var(--font-num);
  font-variant-numeric: tabular-nums lining-nums;
  font-feature-settings: "tnum" 1, "lnum" 1;
  font-weight: 600;
}
```

- **强制 tabular-nums**：所有 KPI、表格数字列、轴标签、时间戳、百分比、计数。目的：数字纵向对齐，列与列之间可做长度比较。
- **禁止用 monospace 字体族**做数字（会连带中文掉字、行高失控）。
- 大数字（≥32px）`letter-spacing: -0.2px ~ -0.5px`（视觉上收紧，避免数字之间"漏风"）。
- 12–14px 数字 `letter-spacing: 0`，**不要负数**（会粘连）。
- 千分位：`1,792` 用半角逗号，禁止空格分隔。
- 时间戳格式统一 `2026-11-06 17:11:24`，`--fs-xs` + `--neutral-3`。
- 百分比统一保留小数位与数据源一致，**不得自行四舍五入**（如 `220.49人` 保持原样）。

### 3.5 行高与字距

- 正文行高 ≥ **1.6**（14px → 22px；12px → 18px）。中文无降部，1.6 是深底下的可读下限。
- 标题行高 1.3（h1/h2）；大数字行高 1.05–1.15（视觉居中，避免上下留白不均）。
- 中文标题加正字距（+0.2 ~ +0.5px）撑开呼吸；**中文正文不加字距**（会破坏连读）。

### 3.6 大屏观看距离校正

| 场景 | 距离 | 校正动作 |
|---|---|---|
| 近端操作席 | ≤ 1.5 m | 按上表基准值，不调整 |
| 指挥席（主投放场景） | 1.5 – 3 m | `--fs-xs` 档的**所有承载数据**内容升为 14px；轴标签维持 12px；其余不变 |
| 远端 / 巡视通道 | ≥ 3 m | display ×1.25（55px）、h1 ×1.20（31px）、h2 ×1.10（20px）、正文下限 14px、**禁止 12px**；表格由「标准密度」切「宽松密度」，同屏行数减少 25% |

**实现方式**：根节点 `data-reading-distance="near | mid | far"` 切换三套字号 token，**不使用** `transform: scale()` 整体缩放（会 rasterize 模糊，且破坏 1px 描边）。大尺寸屏用 `clamp()` 控制大字号自适应：
```css
--fs-display: clamp(44px, 2.3vw, 58px);
--fs-metric:  clamp(32px, 1.7vw, 42px);
--fs-h1:      clamp(26px, 1.4vw, 33px);
/* 小字号一律固定，不参与缩放，保护 12px 地板 */
```

## 4. 间距、栅格与圆角

### 4.1 间距标尺（8pt 基准）

| Token | 值 | 典型用途 |
|---|---|---|
| `--s-1` | 4px | 图标与文字间距、徽标内上下 |
| `--s-2` | 8px | 标题与内容、图表边距、紧凑行内间距 |
| `--s-3` | 12px | 表头左右内边距、卡片紧凑 padding |
| `--s-4` | 16px | 卡片间距、卡片默认纵向 padding |
| `--s-5` | 20px | **卡片默认横向 padding** |
| `--s-6` | 24px | 列 gutter、卡片主 padding（概览卡） |
| `--s-7` | 32px | 页边距（1920）、大区块间隔 |
| `--s-8` | 40px | 页面顶部留白 |
| `--s-9` | 48px | 页边距（≥2560） |
| `--s-10` | 64px | 顶部栏高度 |

> 只用以上 10 档。**禁止**出现 5/7/9/11/13/15px 等奇数间距。

### 4.2 栅格（12 列）

| 视口宽 | 页边距 | Gutter | 列宽 | 内容宽 | 三栏方案 |
|---|---|---|---|---|---|
| ≥ 3840 | 64px | 32px | **280.00px** | 3712px | 3 / 6 / 3 → 904 / **1840** / 904 |
| 2560 – 3839 | 48px | 32px | **176.00px** | 2464px | 3 / 6 / 3 → 592 / **1216** / 592 |
| **1920 – 2559** | **32px** | **24px** | **132.67px** | **1856px** | **3 / 6 / 3 → 446 / 916 / 446** |
| 1440 – 1919 | 24px | 16px | **101.33px** | 1392px | 三栏降 2 栏（中栏 **688** 固定 + 侧栏流式） |
| 1280 – 1439 | 20px | 12px | **92.33px** | 1240px | 单列纵向堆叠，允许整页纵向滚动 |
| < 1280 | 16px | 8px | 流式 | — | 单列 + 表格转卡片行 |

**1920 基准算式**（可直接落 CSS Grid）
```
内容宽 = 1920 − 32×2 = 1856
列宽   = (1856 − 11×24) / 12 = 132.67px
span(3) = 3×132.67 + 2×24 = 446px      ← 侧栏
span(6) = 6×132.67 + 5×24 = 916px      ← 中栏
446 + 24 + 916 + 24 + 446 = 1856 ✓
```

**垂直基准（1920×1080 整屏）**
```
顶部栏           64px
内容区顶部内边距   20px
内容区底部内边距   16px
底部导航（预留）   56px
─────────────────────────────
可用内容高 = 1080 − 64 − 56 − 20 − 16 = 924px
```

**对齐铁律**：同一行内的卡片必须**底边对齐**。实现：父容器 `display:grid; align-items:stretch`，卡片内 `display:flex; flex-direction:column`，图表/表格容器 `flex:1 1 auto; min-height:0; overflow:hidden`。`min-height:0` 是防裁切的关键，缺了它 Flex 子项不会收缩，必然溢出。

### 4.3 卡片内边距规范

| 卡片类型 | Padding | 标题下间距 | 典型高度 |
|---|---|---|---|
| 概览卡（首页 KPI / 健康度） | 24px | 16px | 200–240px |
| 标准业务卡（图表 / 表格） | 20px | 12px | 240–320px |
| 紧凑卡（侧栏预警列表） | 16px | 8px | 自适应 |
| 表格容器 | 20px 20px 12px | 12px | 自适应，表体内部滚动 |

卡片之间间距 `--s-4` 16px；列与列之间用 gutter 24px（不是卡片 margin）。

### 4.4 圆角（3 档，刻意偏小）

| Token | 值 | 使用场景 |
|---|---|---|
| `--r-xs` | **2px** | 徽标 / Tag、柱状图柱顶、进度条端点、色条端点 |
| `--r-sm` | **4px** | 卡片、按钮、输入框、下拉、表格容器（**全站主用**）|
| `--r-md` | **6px** | 悬浮层：Popover、Tooltip、模态框 |

**禁用**：圆角 > 8px；胶囊形（`border-radius: 999px`）仅允许用于状态点与徽标（高度 ≤ 24px）。大圆角在 1920 宽的密集数据界面上会显著降低信息密度观感，且与"精密"对立。

### 4.5 阴影（最多 2 层）

```css
--shadow-1: 0 1px 2px rgba(0,0,0,0.32);                    /* 卡片 */
--shadow-2: 0 4px 16px rgba(0,0,0,0.40);                   /* 悬浮层 */
--inner-hi: inset 0 1px 0 rgba(255,255,255,0.035);         /* 可选：卡片顶部 1px 微高光 */
```
`--inner-hi` 是 1px 的**实线**，不是发光，作用是在深底上给卡片顶部一点"被照亮"的物理暗示，成本极低。可选，默认关闭。

## 5. 核心组件视觉规范

### 5.1 业务卡片

**结构**
```
background : var(--bg-card)        #141E2A
border     : 1px solid var(--border-default)   #2E3D4E   (1.52:1)
border-radius : 4px
padding    : 20px  (紧凑 16px / 概览 24px)
box-shadow : var(--shadow-1)
```

**状态**

| 状态 | 变化 |
|---|---|
| 默认 | 如上 |
| Hover（可点击卡） | `border-color: var(--border-strong)` #3B4C5E；`background: #17222F`；**不加阴影、不加发光** |
| 选中 | `border-color: #5290DA` + `background: rgba(82,144,218,0.06)` + 左侧 2px `#5290DA` 内嵌条 |
| loading | 内容区整体 40% 不透明 + 顶部 2px 进度条（`--blue-600`，宽 0→100%），不用骨架闪烁 |
| 空态 | 12px `--neutral-4` 居中文字 `暂无数据`，高度不低于 120px |
| 错误 | 顶部 1px `--danger-text` + 12px 错误说明，不用红底 |

**关于"顶部 2px 语义色条"——我的判断：改造采纳，但不放顶部**

结论分三句：

1. **采纳**：1px 描边 + 低透明度底 + 精确内边距，这是本方案的层次主干，必须全站统一。
2. **不采纳顶部横条**。理由：① 顶部横条在 8 张卡片并排时会形成"一排通栏横线"，视觉上和旧设计的顶部发光描边**同构**，读者会直接读成"还是那个风格"；② 横条压在标题基线上方，与 `18px` 标题争夺同一视觉通道；③ 横条是"卡片级"的，而语义其实是"条目级"的——卡片里往往混着多个严重度。
3. **替代方案（采纳）**：语义色条改为**左侧垂直 3px**，且**只用于"预警/待办类卡片"**（内容本身即告警集合的卡片）。常规数据卡（图表、KPI、表格）**不加任何色条**，纯靠标题+描边区分。

```
/* 预警类卡片：左侧 3px 竖条 */
.warn-card::before {
  content: ""; position: absolute; left: 0; top: 0; bottom: 0;
  width: 3px; border-radius: 4px 0 0 4px;
  background: var(--sev-color);   /* 取自该卡内最高严重度 */
}
/* 常规数据卡：无色条 */
```
左侧竖条与中文"从上到下、从右到左"的列读方向一致，且不与任何标题、数值争位。它读作"这张卡是一个告警对象"，语义明确，也不模仿旧设计。

### 5.3 KPI 数字块

**结构（推荐形态：同一卡片内的"无缝分栏"，而不是 4 个小盒子）**

原页面 4 个 KPI 各自是独立小卡，各带发光边框——4 个框互相竞争，都不突出。改为**一张卡内 4 格，格间 1px 竖线分隔**，视觉上是一个整体，层级更稳。

```
┌─────────────────────┬─────────────────────┬─────
│ 罪犯分数情况          │ 罪犯被卡管理          │
│ 21  人      ↑ 4.8%   │ 11  人      ↓ 2.1%   │
│ 统计区间 11-01 ~ 11-06│ 统计区间 11-01 ~ 11-06│
└─────────────────────┴─────────────────────┘
```

| 元素 | 规格 |
|---|---|
| 容器 | 卡片底 `#141E2A` + 1px `#2E3D4E`；内部 4 格等分，格间 1px `#26333F` 竖线；每格 padding `20px 20px 16px` |

| 环比 | `12px / 500`，箭头 8px + 数值；**颜色由"好坏"决定，不由"涨跌"决定**：向好 → `#3FC1A7`，恶化 → `#E5746E`，中性量值 → `#77A9E1`；位置：数值右侧 12px，`align-self: baseline` |

### 5.5 预警条目（必须 3 秒可分辨）

**三重冗余编码**（色相 + 文字 + 位置），不依赖单一通道：

```

│ ▌ │ [严重] 人数清点互监身份异常            │  7   │
│ ▌ │ 11-06 17:02 · 监管改造                │  人  │
└───┴──────────────────────────────────────┴──────┘
```

| 严重度 | 左竖条 | 徽标文字色 | 徽标底 / 描边 | 条目底 |
|---|---|---|---|---|
| 严重 | 3px `#E5746E` | `#E5746E` | `rgba(229,116,110,0.14)` / `rgba(229,116,110,0.32)` | `rgba(229,116,110,0.06)` |
| 预警 | 3px `#DC9F46` | `#DC9F46` | `rgba(220,159,70,0.14)` / `0.32` | 透明 |
| 关注 | 3px `#5290DA` | `#77A9E1` | `rgba(82,144,218,0.14)` / `0.32` | 透明 |
| 正常 | 3px `#3FC1A7` | `#3FC1A7` | `rgba(63,193,167,0.12)` / `0.32` | 透明 |

**尺寸**
- 单行条目高 **56px**；含副标双行 **72px**
- 左竖条 3px 通高，不圆角（与卡片圆角脱开，避免"胶囊化"）
- 徽标高 **20px**，padding `0 6px`，`12px / 600`，圆角 2px
- 标题 `14px / 500` `#DCE5EE`，**单行 ellipsis**（禁止换行挤压——换行会让 7 条预警高度不一致，破坏扫视）
- 副标 `12px / 400` `#5F6E80`，格式 `时间 · 来源板块`
- 右侧数值 `20px / 600` `#F2F6FA` + 单位 `12px` `#8494A6`
- 条目间 1px `#26333F` 分割，无卡片包裹（列表是"流"，不是"盒子群"）

**排序显式化（对应 Brief §4-12）**
列表头部右侧固定显示排序依据，且允许切换：
```
按严重度 ↓   ·   17:02 更新        [严重度 | 时间]
```
- 默认排序：严重度降序 → 时间降序
- 切换按钮为 `12px` 文字 tab，激活 `#DCE5EE` + 底部 2px `#5290DA`
- **禁止**平铺无序列表

**3 秒识别的实现逻辑**：色相（红/橙/蓝/绿）+ 文字标签（严重/预警/关注/正常）+ 垂直位置（严重恒在顶部），三通道中任一失效（色弱、远距、截图灰度化）仍可判读。

## 8. 与下游对齐的三条硬约定

1. **前端**：所有数值从本文件 §2–§5 直接复制为 CSS 自定义属性，落在 `:root` 与 `[data-density]` / `[data-reading-distance]` / `[data-theme]` 三个选择器下。**禁止**在组件内写裸色值、裸字号、裸间距。落地顺序建议：token → 布局骨架（含 56px 预留）→ 卡片/标题 → 表格 → 图表 → 预警列表。先做骨架再做组件，可避免"卡片做完发现底边不齐"的返工。
2. **体验**：本方案未改动任何交互模型与信息架构，但提供了 3 条体验侧必须先拍板的点——① 底部导航「固定底部」还是「收进顶部」（§5.8 二选一）；② 首页中间区承载哪个信息模块（§V5.2，影响中栏组件复用）；③ 观看距离定档 `near/mid/far`（§3.6，决定字号是否整体上调一档）。这三点定了，视觉侧不再有变量。
3. **不变式**：本文件未新增、未删除、未重命名任何业务字段。字段清单以 `00-brief.md` §3 为唯一准，视觉只决定"怎么排"，不决定"有什么"。
